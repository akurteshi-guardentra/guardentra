| 21 | ✅ **Invited teammates could not join at all** — `bootstrapUserProfile`'s batch was rejected outright, so multi-user onboarding was broken in production | Found by the task #27 token/role review, caused by KI#13 the day before. The `seatCount` increment was bundled into the same `writeBatch` as the joining member's own profile write. Security rules get **no read-your-writes consistency within a batch**: the `organizations` update rule calls `isOrgMember(orgId)`, which `get()`s `users/{uid}` — the very document that batch was creating — so it evaluated against a non-existent profile and the **entire batch** failed with `PERMISSION_DENIED`, taking the profile write down with it. The rule had been tested in isolation; the batch that used it never was. Fixed by moving the increment after `batch.commit()` in a try/catch: the profile write (the part that must succeed) is no longer coupled to it, and an increment failure now merely undercounts a seat — fail-open, consistent with #12's documented soft-metering — instead of locking the user out. Two emulator cases pin both halves: the bundled batch is rejected, the corrected two-step order succeeds. |
| 22 | ✅ Organization settings were writable by any member, not just admins | Found by the same review.
